## Analysis

The analysis implements experiments/PLAN_E5.md r2 ("Measurement and statistics", "Contrasts", "What the results mean") and its amendments 1 and 2 with E1's statistics, imported from experiments/e1/analyze.py and never changed: the paired sign-flip test (100,000 draws, seed 1), percentile bootstrap intervals (10,000 resamples, seed 1), Holm, E1's verdict rules (model-dependent, helps, hurts, no effect larger than 0.03, inconclusive; under 30 queries "insufficient n"), E1's confound regression and its note, and E1's realized detectable effect. numpy only; `python3 -I` as for E1 to E3.

| File | What it does |
|---|---|
| `analyze_e5.py` | Reads the E5 data, the answer files, score.py's cells and summary, and the earlier runs' cells, versions and prompts; logs the sha256 of every input file; checks that the cells match the answers; writes `out/analysis_e5.json`. |
| `simulate_null_e5.py` | Shuffles version labels within each query (E1's `shuffle_labels`) on null cells and runs the planned code path; writes `out/null_simulation_e5.json`. |
| `report_e5.py` | Writes `out/RESULTS_E5.md` (plain language) and `out/e5_results.json` (one row per contrast: contrast, set, n, d, ci95, ci90, p, p_holm, label, single_model, cross_run, plus the readings) for the paper and the tool; `--secondary` reports `analysis_e5_secondary.json` into `RESULTS_E5_secondary.md` and `e5_results_secondary.json`. |
| `sanitize_e5.py` | Writes the committed aggregates `experiments/results/e5/{analysis_e5.json, e5_results.json, score_summary.json}` from `out/` and refuses when any page-derived text remains (see "Committed aggregates" below). |
| `tests/test_analysis.py`, `tests/test_analysis_report.py`, `tests/test_sanitize_e5.py` | Synthetic cells with known effects for every branch of the plan, the judge and cross-run rules, the reported items, amendment 3's sensitivity rows, the report and the null simulation; one test checks that E1's functions are called with E1's settings; the sanitizer's quote rule and page-text check. |

### Steps, after the answers are copied back

```
python3 -I experiments/e1/score.py --data experiments/e5/data --out experiments/e5/out --sets main,e3,e3-four,replication
python3 -I experiments/e5/analyze_e5.py
python3 -I experiments/e5/report_e5.py
```

**Any run of `analyze_e5.py` into `experiments/e5/out` fixes the planned snapshot, a dry run included.** A dry run (to check the pipeline on partial answers, say) must write elsewhere: `python3 -I experiments/e5/analyze_e5.py --out <scratch folder>` reads the cells from `experiments/e5/out` (`--scored`, the default) and leaves `out/analysis_e5.json` unwritten; `python3 -I experiments/e5/report_e5.py --out <scratch folder>` reports it there.

The analysis runs once. The sha256 of every input file is printed when it starts and written into `analysis_e5.json`: E5's data files, every `data/answers/*.jsonl`, score.py's `cells.jsonl`, `score_summary.json` and `scores.jsonl` (all three required), and the earlier runs' cells, versions, applicability and prompts. Before anything is computed it refuses when the cells do not match the answers: score_summary's answered count for any (set, judge, version) differs from the answers counted in `cells.jsonl`; the answer files hold more distinct keys than score_summary counted (answers copied back after score.py ran, or a set left out of `--sets`); one key holds two different answers; or E1's own scoring, run again on the answer files as they are now, does not give back score.py's outputs exactly (every `scores.jsonl` row re-scored from its answer with `score.score_answer` at its slot, and the cells rebuilt from the scores with `score.make_cells`, compared field by field with `cells.jsonl`). The last check catches an answer file replaced in place after scoring with the same keys; an answer whose text changed without changing any score passes, with its file's new sha256 in the snapshot. On E1's real answers (17,824) it gives E1's `scores.jsonl` and `cells.jsonl` back exactly in 2.6 s, so E5's (about 31,600 at most) add about 5 s. Rerun score.py, then the analysis. If `analysis_e5.json` already exists from a different snapshot, the script refuses; `--secondary` writes `analysis_e5_secondary.json`, marked secondary, which changes no label, and `report_e5.py --secondary` writes `RESULTS_E5_secondary.md` from it. `--no-earlier` skips the earlier runs (no drift check, no fallback).

### Committed aggregates

```
python3 -I experiments/e5/sanitize_e5.py --check experiments/RESULTS_E5.md
```

writes `experiments/results/e5/` from `out/`. Page-derived text is the pages' titles and texts, every version's title and text and q_G; queries, q' and q_L are not. It first applies E2's rule (commits c8e5fc6, 01f4b67) to validator messages only: a quoted fragment becomes '…', and a quote mark inside a word (an apostrophe) never opens one. Then it checks every string and key of the three files, and of each `--check` file, for a run of 6 words from a page-derived text, or a whole title or q_G of 3 to 5 words; a run that also occurs in our own code (E1's and E5's scripts, the engine bundles, the engine's sources) is authored and passes. Any hit stops it before it writes (the run itself is never printed). On E5's outputs (2026-11-03): nothing to replace, and 0 of 6,259 word runs in 8,046 strings occur in any of the 7,093 page-derived texts, so the committed files equal `out/`'s byte for byte. biome is not run on them: `biome.json` excludes `experiments/results`, and E1 to E3's aggregates use the same `write_json` format.

### Null simulation

Before the freeze (and again only if the structure changes before any answer exists):

```
python3 -I experiments/e5/simulate_null_e5.py          # 1 to 2 minutes, fixed seed
```

It uses E5's real `edit_texts.jsonl`, `versions.jsonl` and `applicability.jsonl` for the queries, applicability and deterministic versions (original, 9, 9P, 9K, 9A, 9G) and draws only the versions built on the cluster (9L, 12K, P12K, 12, P12) at the pre-run rates (`--synthetic` uses a synthetic layout instead). On the structure as rebuilt at 2026-11-03 02:34 PST (edit texts `fa16a8c9...`, versions `17d0d136...` with E1's own 12 and P12 added per amendment 2, applicability `c37ea338...`), 1,000 simulations (rerun 02:55 to 02:56 PST, 57 s; output sha256 `b1071031...`) gave:

- **The gate alone: 4.8%** (Monte Carlo SE 0.7%) significant, its own two-sided level. This is also the "gate plus Holm family" headline (`structure.familywise_false_positive_rate`), and necessarily so: a gate that passes is a significant gate, so the structure can never exceed the gate's own rate under the global null. It does not test the family.
- **The family itself:** the four guess tests with Holm's correction gave a false positive in **4.4%** (MC SE 0.6%) of simulations if they were never gated (`family_if_never_gated.holm`; 15.9% without Holm), and in **0.2%** after the gate passed (`structure.family_significant_after_gate`). These are the numbers that check the Holm family.
- The replication family 4.4%; 12K vs P12K 3.9%; step 5 4.6%. (On the earlier structure, versions `b98ef99b...`: gate 5.0%, family never gated 5.2%, after the gate 0.3%, replication 3.5%, 12K vs P12K 4.9%, step 5 4.9%; the draws differ because the structure did.)

PLAN_E5 amendment 2 puts the output under `experiments/e5/freeze/`: the freeze commit copies `out/null_simulation_e5.json` (gitignored) to `experiments/e5/freeze/null_simulation_e5.json`, and `report_e5.py` reads that copy when `out/` has none.

### Inputs

- E5: `data/edit_texts.jsonl` (set and stratum per query, key-term count, template), `data/versions.jsonl` (E1's schema plus `edit_text`, `same_sentence_as_9`, `tool_gate` and the tool's coverage flags), `data/applicability.jsonl` (required), `data/prompt_build.json` (refused queries), `data/prompts.jsonl` (for the prompt check), `data/answers/*.jsonl` (hashed and counted), and score.py's `out/cells.jsonl`, `out/score_summary.json` and `out/scores.jsonl` (all required; the answers are re-scored against them).
- Earlier runs, for the drift check and the cross-run fallback: E1 (`e1/data`, `e1/out`: original, 9, 12, P12), E2a (`e2/data`, `e2/out/a`: 9P), E3 (`e3/data`, `e3/out/new`: the new queries' originals), each with its `versions.jsonl` and `prompts.jsonl` (and E1's `applicability.jsonl`). A missing earlier file is warned about on stderr and listed under `snapshot.warnings` (and in the report), never skipped silently. Only cells and versions of the four scored sets (main, e3, e3-four, replication) enter, from E5 and from the earlier runs, so a smoke or timing cell can never stand in for a real one.
- On the data built so far (checked end to end with fake answers on E5's real prompts, 2026-11-03 02:51 PST, E5 versions `17d0d136...`): every E5 original, 9, 9P, 12 and P12 whose earlier answers exist has the same title and text and the same prompts, seed by seed, as the earlier run's version (1,230 cells checked, 0 differ); the other 52 earlier cells are E1's replication-set 12 and P12, which E5 does not run and no contrast uses. 19 files hashed, 0 warnings, 23,572 answers re-scored with 0 differences, 2,950 cells rebuilt with 0 differences; analysis 6 s.

### Choices the plan leaves open

Each is the reading closest to E1's code, fixed before any E5 answer exists.

1. **"Helps" includes E1's note** ("helps, possibly through length or query-term overlap") in the gate, the Holm family and the retention reading: PLAN_E5 amendment 2. It matters: the confound regression's intercept is the effect at no change in key-term count, which arm 9 never has (it adds the query's words by design), so a real constant arm 9 effect usually carries the note (E1's own arm 9 did). The same reading is used for step 4's rule ("12K vs P12K helps"), which amendment 2 does not name; it is the reading closest to E1, whose tool gives the noted label the measured label with the note. It is likely to decide step 4: arm 12 adds the query's missing words by design, so in E1's 33 main-set 12 vs P12 pairs the key-term change (12 minus P12) runs from 1 to 23 and is never 0, and E1's own 12 vs P12 label carried the note. Until the plan names it (amendment proposed below), it is a choice fixed here before any E5 answer; the output flags `missing_words.rests_on_e1_note` when the measured label holds only through it, and the report says so. Any other gate label leaves the four guess tests "descriptive (gate failed)", with their numbers still reported.
2. **A gate that is not "helps"** (hurts, model-dependent, too few queries, no effect, inconclusive, or not run): no reading is drawn from the guesses and the reader's-words label follows step 5 (amendment 2). For no effect or inconclusive the paper sentence is the plan's ("reported plainly next to E1's result"); for the others it says no reading is drawn. With a gate that passes, a retention contrast with too few queries or no answers draws no reading (E2's precedent: "the plan gives no reading for this pair of labels").
3. **Retention.** Read only when the gate passes (otherwise "descriptive (gate failed)", with d(G - 9) and both intervals still given), on all main queries with valid G and 9. The rules are applied in the plan's order: keeps, then loses, then partly kept. When both hold (a guess significantly below the exact question but by less than 0.015) the reading is "keeps the gain", the output flags `both_rules`, and the paper sentence and the report add that the exact question still did better, by less than 0.015 (amendment 2).
4. **12K's tool rule:** "12K vs original above 0" is read as its mean d above 0 (no test; a mean d of exactly 0 or no answered query does not pass). Covered by the same proposed amendment.
5. **Judges, per contrast.** A complete cell has all 8 answers. Gemma's queries are those with complete Gemma cells for both versions; the contrast uses both judges only if Qwen has complete cells for both versions of every one of them, from the same run; otherwise it uses Gemma alone for all of them (single-model), and Qwen's own complete queries are reported as secondary. A cell with fewer than 4 valid answers removes the query, as in E1.
6. **Cross-run fallback, per query.** For each query of a contrast, in order: both versions from E5 when E5's cells are complete for both; else both from one earlier run (the same run) when it answered both; only else one version from each source, E5's where complete. So run drift enters d only when no same-run pair exists (for example E5's 9P against E1's 9, since E1 never answered 9P). An earlier cell is used only when the earlier run answered the same version (identical title and text) with the same prompts (every seed's prompt and slot, compared by sha256 against E5's `prompts.jsonl`); each check applies when both sides are known, and the counts are in `earlier_cells_check`. A query with no usable pair is left out. Any earlier cell flags the contrast "cross-run", with the pairs counted as `mixed` (E5 with an earlier run), `earlier_one_run` and `earlier_two_runs`. Switching a whole column to the earlier run would throw away pairs answered within E5.
7. **Arm 12 on E1's queries.** Amendment 2 re-answers E1's valid 12 and P12 versions on its main queries in tier 3, so the pooled "12 vs P12" and "12K vs 12" are within E5 when tier 3 runs. If tier 3 is cut, or until E5's versions file carries those rows, they fall back to E1's own versions and answers (both from E1, `earlier_one_run`) and are flagged cross-run.
8. **Applicability.** A version is applicable when its own row and its parent's row allow it (9P, 9K, 9L, 9A, 9G need arm 9's row; P12 needs 12's; P12K needs 12K's); a missing row counts as applicable, as in E1. E1's frozen table is the only fallback, never E3's (which marks arms 9 and 12 not applicable). Set and stratum come from `edit_texts.jsonl`.
9. **Per stratum, per judge and reweighted** are the pooled planned contrast restricted to the stratum's queries (same judges and runs), not new contrasts. The reweighting weights are the key-term-level shares of E1's 80 main queries; a level with no new query in a contrast is dropped and the rest renormalized (flagged as `levels_missing`); the 95% interval resamples the new queries with E1's bootstrap indices.
10. **Query-length cells** are built on the queries of d(9K - 9). The first cell under 10 queries, in level order, joins the next cell (the last cell joins the previous one), repeated until every cell has 10 or one cell is left. d(9 vs original) is given in the same cells, on its own queries.
11. **Template and tool-gate splits.** Both 9K and 9L are split by the template the tool used for q' ("kept" against "what-is" or "how-to"). The tool-gate subset uses 9K's `tool_gate` (question coverage with q' under 0.9) for both, as the plan says "given q'"; 9L's own flag (given q_L) is reported beside it.
12. **Share kept.** Ratio of the mean of d(G - 9P) to the mean of d(9 - 9P) on the queries with G, 9 and 9P, both on the same judges (Gemma alone if either contrast is single-model), with a 90% percentile interval from E1's bootstrap indices (seed 1). Not estimable when the denominator's 95% interval includes 0 or more than 2.5% of resamples give a denominator at or below 0. d(G - 9) is always given, on its own queries. E1's queries are reported separately with the selection caveat.
13. **The ladder** follows the plan's directions: 9A vs 9K (the words the keyword drops), 9 vs 9A (the exact-string echo), and 9 vs 9K on the queries where 9K copies the same sentence as 9; positive d means the version with more of the reader's words was cited more. All "reported without a verdict" items are given for both sets where their versions exist; on the replication set d(9K - 9) and d(9L - 9) are added without a verdict.
14. **Detectable effect** is E1's realized formula at the step's alpha: 0.05 for the gate, 12K vs P12K and step 5; 0.05/m (the strictest Holm step, as E1) for the family members; 0.05 for reported items.
15. **Drift check.** Per (query, version, judge): E5 cell minus the earlier cell (both complete and not dropped), averaged per query, with E1's bootstrap 95% interval and sign-flip p, overall, per judge, per version, per set and per earlier run (E1, E3).
16. **Validity counts**, per version and set (and per stratum on the main set): queries; not applicable, counted from the applicability rows (the version's own row or its parent's, so the arm 9 family shows the queries where arm 9 does not apply) plus versions the editor marked not applicable, each by reason; applicable, valid, failed validation by reason; versions still missing in the snapshot (for a placebo, only where its edit is valid); mean length ratio and key-term change of the valid versions; and, for each tool flag, the share of valid versions it marks True (covers the edit text, covers q, would suggest the edit). Reasons are cut to the message's head with numbers replaced by #, so no page word appears and like reasons group together. Arm 12 rows are not shown for the replication set, where E5 runs no arm 12.
17. **Null simulation labels** skip E1's per-judge "model-dependent" check and the confound note, so the label-based rates can only overstate false positives; the headline rate is E1's definition (any Holm-significant test).
